# Supabase 게시판 설정

이 기능은 **표시 이름 + AI 평가 항목만** 공개 저장합니다. 원문, 업로드 파일, 파일명, 요약, 맞춤법 교정, Gemini API 키는 DB에 전송하지 않습니다. 평가 자체에 AI가 원문을 인용할 수 있으므로 저장 전에 사용자가 공개 미리보기를 확인합니다.

## 1. Supabase 프로젝트에 DB 생성

Supabase 프로젝트 → SQL Editor에서 `supabase/migrations/202610190001_public_reviews.sql` 파일 전체를 **한 번** 실행합니다. 이미 적용된 마이그레이션을 반복 실행하지 마세요. 기존 테이블을 삭제하지 않는 신규 마이그레이션입니다.

- `public_reviews`: 작성자 이름, AI 평가 JSON, 작성일, 브라우저 소유 식별자.
- `review_feedback`: 이름, 선택 별점(1~5), 선택 댓글(최대 1,000자), 날짜, 브라우저 소유 식별자.
- `review_feed`: 별점 평균과 별점·댓글 수를 함께 조회하는 뷰.
- RLS 활성화, `anon`/`authenticated` 직접 접근 차단. Vercel 서버만 secret key로 접근합니다.
- 회원 로그인이나 Supabase Anonymous Sign-ins 설정은 필요하지 않습니다.

## 2. Vercel 환경 변수

Vercel → 프로젝트 → Settings → Environment Variables에 아래 값을 입력합니다. Production과 필요한 Preview 환경을 지정하고 **Redeploy** 합니다.

| 이름 | 값 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL (`https://…supabase.co`) |
| `SUPABASE_SECRET_KEY` | Supabase의 `sb_secret_…` 키. 기존 프로젝트의 `service_role` 키도 지원 |
| `SESSION_SECRET` | 32자 이상의 임의 문자열. 아래 명령으로 생성 권장 |

```sh
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Secret/service_role 키는 **서버 전용**입니다. `public/`, GitHub, HTML에 넣지 마세요. Publishable/anon 키는 이 설계에서 사용하지 않습니다. 분석용 Gemini 키는 이전처럼 사용자가 화면에서 입력합니다.

`SESSION_SECRET`은 재배포 때 유지하세요. 변경하면 기존 브라우저의 작성자 권한과 아직 저장하지 않은 평가 서명이 무효화됩니다. 환경 변수가 없으면 분석은 계속 동작하고 게시판은 준비 중으로 표시됩니다.

## 3. 동작

1. 보고서 분석 후 결과 아래에서 이름을 입력합니다.
2. ‘저장되는 평가 미리보기’를 확인하고 공개 동의에 체크한 후 ‘평가 공개 저장’을 누릅니다.
3. 공개 게시판에서 모든 방문자가 AI 평가를 읽을 수 있습니다. 보고서 원문은 볼 수 없습니다.
4. 다른 브라우저의 방문자는 이름과 함께 별점 또는 댓글(둘 다 가능)을 등록합니다.
5. 같은 브라우저에서는 내 의견 수정·삭제 및 내 공개 평가 삭제가 가능합니다. 평가 삭제 시 연결된 의견도 삭제됩니다.
6. 목록과 열린 평가의 의견은 30초마다 자동 갱신됩니다. 새로고침 버튼도 제공합니다.

## 보안·운영 범위

- 이름은 **본인 인증되지 않은 표시 이름**입니다. 로그인 없이 이용하는 게시판이며 개인별 계정 인증이 아닙니다.
- 서버 서명된 HttpOnly·SameSite=Strict 쿠키로 같은 브라우저를 식별합니다. 운영 HTTPS에서는 Secure도 설정됩니다. 다른 브라우저/기기나 쿠키 삭제 후에는 이전 작성자 권한이 복구되지 않습니다. 삭제 요청은 운영자가 Supabase Table Editor에서 처리할 수 있습니다.
- 브라우저당 평가당 의견 하나를 upsert합니다. 쿠키 삭제나 다른 브라우저로 재등록할 수 있으므로 엄격한 1인 1표 보장은 하지 않습니다.
- AI 평가 저장은 서버가 발급한 24시간 유효 서명으로 검증합니다. 클라이언트가 임의로 만든 평가나 타인의 서명은 거부합니다. 같은 평가 중복 저장 요청은 같은 ID로 처리합니다.
- 서비스 키가 RLS를 우회하므로 서버 API가 소유자 검증과 입력 제한을 수행합니다. 공개 API 응답에는 내부 소유 식별자가 포함되지 않습니다.
- DB 트랜잭션 잠금으로 같은 브라우저의 동시 작성 요청을 정리합니다. 평가 최대 10개/시간(현재 남아 있는 게시물 기준), 의견 간격 최소 5초, 최근 1시간 업데이트한 의견 최대 30개를 제한합니다. 계정/IP 기반의 강력한 악용 방지는 별도 기능입니다.
- 게시판에 HTML을 직접 삽입하지 않고 출력 문자열을 이스케이프합니다. 자동 갱신 중 입력 중인 댓글은 유지합니다.
- 공개·댓글·삭제는 버튼을 눌러야 실행됩니다. 분석만으로 DB에 자동 저장되지 않습니다.
- Supabase 프로젝트와 Vercel 관리 연결이 제공되지 않은 환경에서는 SQL 적용/환경 변수 설정/실서비스 데이터 검증을 자동 완료할 수 없습니다. 코드는 배포 준비가 되어 있어도 이 설정은 최초 1회 필요합니다.

## 배포 후 확인

- 브라우저 A에서 분석 → 평가 미리보기 → 이름·동의 → 공개 저장.
- 브라우저 B에서 평가 조회 → 별점과 댓글 → 새로고침 후 유지 확인.
- A에서 B의 댓글을 삭제할 수 없는지, B에서 A의 평가를 삭제할 수 없는지 확인.
- A의 평가 삭제 시 연결된 댓글도 사라지는지 확인.
- Supabase 테이블에 원문·요약·교정·API 키가 없는지 확인.

공식 자료: [Supabase API 키](https://supabase.com/docs/guides/getting-started/api-keys), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
